# 目录结构

**[← 回到首页](../README.md)**

自 1.0.0 起，这个仓库是**插件项目搜集器**。它做三件事：**采集**（每 6 小时搜一遍新插件、
并按 `owner/repo` 点名把已知项目的 star 数与最近推送刷准）、**展示**（侧栏「插件搜集」面板）、
**复制**（把 `github:owner/repo` 放进剪贴板）。安装交给 harness 官方客户端，本仓库不分发任何插件字节。

> ★ **仓库根就是插件包。** 官方桌面版的安装规格解析器只接受 `host/owner/repo`
> 形状的地址，仓库子目录会被直接拒绝。所以 `package.json` / `cordis.patch.yml` /
> `src/` 必须躺在根上 —— 1.0.0 把插件从 `plugins-src/dsh-plugins-market/` 搬到了这里。

## 一、完整目录树

```none
dsh-plugins/
├─ package.json                # ★ 插件清单：main / exports / dsh.bundle / dsh.client
├─ cordis.patch.yml            # ★ 装配补丁：把本包插进插件树（id = name = 包名）
├─ compatibility.json          # ★ 跨版本实测矩阵（不构成闸门，只记录「谁跑过」）
├─ README.md                   # 首页：这是什么 / 怎么装 / 怎么用 / 数据怎么来
├─ CONTRIBUTING.md             # ★ 贡献规范：收录流程 / 四条规矩 / PR 检查清单
├─ LICENSE                     # MIT
├─ .gitattributes              # 行尾与二进制标记（catalog/ 不做 diff 展开）
├─ .gitignore                  # 忽略 .cache/ 等本地产物
├─ src/                        # ★ 插件本体（服务器半 + 客户端半）
│  ├─ server/
│  │  ├─ index.js              #   cordis 入口：路由注册 + 三个 RPC（index/status/refresh）
│  │  ├─ catalog.js            #   索引层：读取顺序、条件请求、列式出参
│  │  ├─ compat.js             #   适配层：harness 版本探测 + 能力探测（永不拦截）
│  │  └─ util.js               #   基础设施：路径、读写、版本解析
│  └─ client/
│     └─ app.js                # ★ 客户端半（classic script，不打包不转译）
├─ catalog/                    # ★ 数据：采集结果
│  ├─ index.json               #   全部记录（唯一事实来源，一条记录一行）
│  ├─ snapshot.json            #   稳定投影：完整目录，打进插件包当离线兜底
│  └─ seed.json                #   人工：include（补录）/ exclude（下架）
├─ scripts/                    # ★ 采集器
│  ├─ collect.mjs              #   唯一会写 catalog/ 的脚本
│  └─ lib/
│     ├─ catalog-format.mjs    #   记录格式：归一化 / 合并 / 排序 / 确定性序列化
│     ├─ github.mjs            #   GitHub 传输层：REST 搜索 + GraphQL 点名直读、限流退避
│     ├─ reconcile.mjs         #   对账层：观测 → 索引（没看过就不删 / 改名迁移）
│     └─ refresh.mjs           #   排班：本轮直读哪 1/4 的目录（按配额切份）
├─ test/                       # ★ 测试（不联网、只读，CI 里全跑）
│  ├─ run.mjs                  #   入口：node test/run.mjs
│  ├─ harness.mjs              #   极简断言框架（不引第三方依赖）
│  ├─ manifest.test.mjs        #   清单与跨版本装载的不变量
│  ├─ format.test.mjs          #   记录格式的确定性
│  ├─ github.test.mjs          #   GraphQL 查询拼装 / 响应解析 / 配额耗尽
│  ├─ reconcile.test.mjs       #   没看过就不删、排班不覆盖旧值、改名迁移
│  ├─ refresh.test.mjs         #   排班：4 个窗口不重不漏
│  ├─ catalog.test.mjs         #   列式出参的契约
│  ├─ compat.test.mjs          #   版本比较与能力探测
│  ├─ server.test.mjs          #   端到端：假宿主 + 真 HTTP 处理器
│  ├─ bundle.test.mjs          #   客户端半的静态约束
│  └─ data.test.mjs            #   对着仓库里真实索引跑自洽校验
├─ docs/                       # 深度文档（首页只放链接）
│  ├─ 目录结构.md               #   本文件
│  ├─ 采集说明.md               #   四路来源 / 合并规则 / 排班 / 三条硬规矩
│  ├─ 数据格式.md               #   index.json 每个字段的含义与来源
│  ├─ 面板说明.md               #   RPC 契约 / 性能做法 / 错误处理
│  └─ 版本兼容.md               #   跨版本适配策略与踩过的坑
├─ assets/
│  └─ hero-everything-is-a-plugin.svg   # 首页配图（纯矢量）
└─ .github/workflows/
   ├─ collect.yml              # ★ 每 6 小时采集并提交（内容没变就不提交）
   └─ verify.yml               # push / PR 上的只读校验（完全不联网）
```

**不在这里的东西**：插件的 tarball、`lib/` 构建产物、任何第三方插件的字节。
插件由各自的作者在他们自己的仓库里发布，本仓库只记录它们的**公开元数据**。

## 二、三层结构，三种职责

| 层 | 回答什么问题 | 可变性 | 谁在读它 |
|---|---|---|---|
| `catalog/index.json` | 「GitHub 上有哪些 DSH 插件项目」 | 每 6 小时采集刷新（内容变了才动） | 面板运行时会从仓库 raw 拉这一份 |
| `catalog/snapshot.json` | 「没网时至少能看到什么」 | 上面那份的**稳定投影**，随索引同一次提交 | 打进插件包的离线兜底 |
| `catalog/seed.json` | 「哪些是人工补的、哪些明确不要」 | **只能由人改** | 采集器 |

单向关系：快照由索引派生，索引由采集派生。**没有反向依赖** ——
所以不存在「改了界面导致数据变化」这种循环。

## 三、为什么只有一份数据文件

上一版是「一个插件一个配置文件」（8780 个 JSON），理由是「某个插件变了，
diff 里只有那一个文件的一行」。

这一版没有沿用那个结构，因为要付的代价变了：

| | 一个插件一个文件 | 单一索引，一条记录一行 |
|---|---|---|
| diff 可读性 | ✅ 一次只看一个文件 | ✅ 一次只看一行 |
| 目录体积 | 8780 个文件、24MB | 1 个文件、约 13MB |
| 克隆成本 | 高（每个 `github:` 安装都要拉一遍） | 低 |
| 单条修订 | 能单独改一个插件 | 也能（改一行） |

> 关键点是：**「一条记录一行」同时拿到了两个好处**。既然 diff 的可读性不再依赖
> 文件切分，那就没有理由付 8780 个文件的代价。

## 四、机器可读的几份数据

| 文件 | 谁维护 | 作用 |
|---|---|---|
| `catalog/index.json` | **脚本生成，禁止手写**（`node scripts/collect.mjs`） | 全部记录：描述 / 地址 / 作者 / star 数 / 语言 / topic / 许可 / 最近推送 |
| `catalog/snapshot.json` | **脚本生成，禁止手写** | 完整索引的稳定投影（时间戳清空） |
| `catalog/seed.json` | **人工** | `include` 补录、`exclude` 下架 |
| `compatibility.json` | **人工 + 实测** | 哪些 dsh 版本真的跑过；**不是闸门** |
| `package.json` | **人工** | 插件清单；没有 dependencies / peerDependencies |
