# 数据格式

**[← 回到首页](../README.md)**

只有两个数据文件，都是 `scripts/collect.mjs` 生成的，**不要手写**。

---

## 一、`catalog/index.json`

```jsonc
{
  "schemaVersion": 2,
  "generatedAt": "2026-09-27T10:00:00.000Z",   // 只在内容真的变了时推进
  "counts": {
    "total": 9423,
    "bySource": { "github-repo": 9001, "github-search": 1369, "public-index": 8933 },
    "archived": 5,
    "withDescription": 8634
  },
  "sources": [                                   // 这一轮每一路采到了多少、有没有失败
    { "kind": "github-search", "label": "GitHub 搜索", "url": "https://github.com/search",
      "found": 1369, "failed": false, "queries": [{ "query": "topic:dsh-plugin", "found": 300, "pages": 3, "error": null }] },
    { "kind": "seed", "label": "手工收录", "url": "catalog/seed.json", "found": 0, "failed": false },
    { "kind": "github-repo", "label": "GitHub 直读", "url": "https://github.com",
      "found": 15197, "failed": false, "partial": false,   // 默认整份刷；中途停下才会 partial
      "planned": 15197, "covered": 15197, "skipped": 0 },  // 没刷到的原样保留
    { "kind": "public-index", "label": "公开索引", "url": "https://…/plugins.json", "found": 8855, "failed": false }
  ],
  "note": "…",
  "plugins": [                                   // ★ 一条记录一行
    { "id": "owner/repo", "owner": "owner", "name": "repo", "url": "https://github.com/owner/repo",
      "description": "…", "descriptionZh": null, "author": "owner",
      "stars": 1234, "forks": 56, "language": "TypeScript", "topics": ["dsh-plugin"],
      "license": "MIT", "homepage": null, "pushedAt": "2026-09-26T15:42:06.000Z",
      "archived": false, "sources": ["github-repo", "github-search", "public-index"],
      "firstSeenAt": "2026-09-17T15:55:14.674Z", "lastSyncedAt": "2026-09-27T10:00:00.000Z" }
  ]
}
```

### 字段表

| 字段 | 类型 | 含义 | 来源 |
|---|---|---|---|
| `id` | string | `owner/repo`，**唯一键** | 采集时归一化 |
| `owner` | string | 作者（GitHub 账号名，保留原大小写） | 由 `id` 推出 |
| `name` | string | 仓库名 | 由 `id` 推出 |
| `url` | string | `https://github.com/<id>` | 由 `id` 推出 |
| `description` | string \| null | **项目描述**（英文原文优先，最长 600 字符） | GitHub 仓库描述 / 公开索引 |
| `descriptionZh` | string \| null | 中文描述（采集源提供时才有） | 公开索引 |
| `author` | string | 作者，与 `owner` 同值（单独留一列是为了将来能接住别的来源） | — |
| `stars` | number \| null | **收藏量** | GitHub 直读 / 搜索 / 公开索引 |
| `forks` | number \| null | fork 数 | 同上 |
| `language` | string \| null | 主语言 | GitHub |
| `topics` | string[] | GitHub topic（小写、去重、排序、最多 50 字符） | GitHub topics / 公开索引 tags |
| `license` | string \| null | SPDX 标识（`NOASSERTION` 视为未知） | GitHub |
| `homepage` | string \| null | 项目主页 | GitHub |
| `pushedAt` | string \| null | 最近推送时间（ISO） | GitHub 直读 / 搜索 |
| `archived` | boolean | 仓库是否已归档 | GitHub |
| `sources` | string[] | 这条是从哪几路知道的（排序后） | 采集器 |
| `firstSeenAt` | string \| null | 第一次看到它 | 采集器（**传承，不重写**） |
| `lastSyncedAt` | string \| null | 最后一次看到它（内容变了才推进） | 采集器 |

`sources` 的取值只有四个：

| 值 | 含义 |
|---|---|
| `github-search` | 在 GitHub 搜索里被发现（也带回当时的元数据） |
| `github-repo` | 被按 `owner/repo` 点名直读过（star 数、最近推送以它为准；改名也由它带回来） |
| `seed` | 来自 `catalog/seed.json` 的人工收录 |
| `public-index` | 来自第三方公开索引（覆盖面最广，但数字可能滞后） |

**没有的字段**：安装方法、版本号、信任分级、体检结论、sha256、tarball 地址。
那些都属于「市场」的职责，1.0.0 全部删掉了。

### 三条不变量（`--check` 会验）

1. **顺序**：`stars` 降序 → `id` 升序。排序只在采集端做一次。
2. **无重复**：`id` 唯一。
3. **可原样往返**：把文件读进来重新序列化一次，必须逐字节相同。

## 二、`catalog/snapshot.json`

与 `index.json` **同构**，只有三处不同：

| 不同点 | 值 | 为什么 |
|---|---|---|
| 条数 | 完整目录，与索引一致 | 新设备离线安装也能搜索全部项目；文件体积上限为 16MB |
| `generatedAt` | `null` | 是「什么时候查的」，不是内容 |
| `firstSeenAt` / `lastSyncedAt` | `null` | 同上 |

> **它是索引的稳定投影**，这个性质有测试盯着（`test/format.test.mjs`）：
> 索引里**只有时间戳**变化时，快照必须逐字节不变；内容真的变了才跟着变。
>
> 不这么做的话，每 6 小时一次的采集都会改到插件包 —— 而包内容变了、版本号没变，
> 装过的人收不到任何更新，git 里却天天多一个 diff。

## 三、`catalog/seed.json`

```jsonc
{
  "_comment": ["…"],
  "include": ["owner/repo"],   // 补录：搜索与公开索引都漏掉的
  "exclude": ["owner/repo"]    // 下架：无论哪一路发现了都不进索引
}
```

★ `include` 里**不要写**描述和 star 数：联网采集时会去 GitHub 直读，
手写的数字一定会过期。人工只回答「收不收」，不回答「它有多少星」。

## 四、面板拿到的不是这个文件，而是它的**列式投影**

`catalog/index.json` 是给人读、给 git diff 看的（字段全、可读性好）。
面板拿到的是同一份数据的压缩形式（见 [`面板说明.md`](./面板说明.md)）：

```
{ meta, total, cols: ["id","desc","descZh","stars",…], rows: [["a/b","描述",…], …] }
```

两个原因：字段名不必重复几千遍（体积约降到 55%），前端也能按需懒还原 ——
只有真正进视口的那十几行才需要变成对象。

列名表在 `src/server/catalog.js` 的 `COLUMNS`，顺序就是契约，
改动等于前后端同时串列，所以它有一条专门的测试。
