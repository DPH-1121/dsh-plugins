# 面板说明

**[← 回到首页](../README.md)**

面板 = 服务器半（`src/server/`）+ 客户端半（`src/client/app.js`）。
它只做**搜集与展示**：不装任何东西、不执行任何命令、不写 profile。

---

## 一、两个半怎么接上

```none
cordis.patch.yml
  └─ insert: [{ id: dsh-plugins-market, name: dsh-plugins-market }]
       ├─ 服务器半：package.json 的 main        → src/server/index.js
       └─ 客户端半：package.json 的 exports["./client"] → src/client/app.js
```

三个 id 不要混：

| 名字 | 在哪 | 作用 |
|---|---|---|
| `dsh-plugins-market`（`name`） | `cordis.patch.yml` | **真实包名**，同时是 boot 图行 id 与 `__ModuleLoader__.load` 的注册键 |
| `id` | `cordis.patch.yml` 的 insert 行 | loader 行 id，只用于 patch 定位 / 禁用 |
| `PANEL_ID` | 客户端半 | 侧栏图标 id 与 `main` slot 的 key，**两者必须同名** |

## 二、RPC 契约

一条同源路由：`POST /dsh-plugins-market/api`

```jsonc
// 请求
{ "method": "index", "args": { } }
// 响应
{ "ok": true, "result": { … }, "tookMs": 12 }
{ "ok": false, "error": "…", "detail": "…" }
```

**只有三个方法**（客户端半里有一条测试钉住这个集合）：

| 方法 | 参数 | 返回 | 说明 |
|---|---|---|---|
| `index` | `{ refresh?: boolean }` | `{ meta, total, cols, rows }` | 列表数据。整份一次给完（列式 + gzip） |
| `status` | — | `{ panel, harness, caps, capsNotes, cache }` | 面板自述 + harness 版本与能力探测。**永远瞬时**，不载入索引 |
| `refresh` | `{ force?: boolean }` | `{ changed, firstLoad, meta }` | 去远程确认一次（条件请求；通常只有 304） |
| `dropCache` | — | `{ ok, cache }` | 丢掉**自己的**磁盘缓存（面板「关于 → 清缓存重取」用） |

> 旧版（插件市场）在这条路由后面挂了 `install` / `installProgress` / `installAbort` /
> `uninstall` / `repair` / `verify` / `bootVerify` / `rollback` / `installPlan` …
> 这一版全部删除。
>
> **现在这条路由不碰 harness、不碰 profile、不执行任何命令**：前三个方法只读数据，
> `dropCache` 删的是本插件自己写在 `~/.dsh/storages/dsh-plugins-market/` 下的缓存文件
> （删掉只会让下一次重新下载）。所以「面板出问题」不可能波及 harness 本身。

### `index` 的出参

```jsonc
{
  "meta": {
    "generatedAt": "…", "counts": {…}, "sources": […],
    "source": "checkout",          // checkout | cache | remote | remote-304 | bundled
    "error": null,                 // 取数过程中的问题（如实回报，不吞）
    "fetchedAt": 1758967200000, "ageMs": 120000, "ttlMs": 1800000,
    "url": "https://raw.githubusercontent.com/…/catalog/index.json",
    "repoHomepage": "https://github.com/DPH-1121/dsh-plugins",
    "truncated": false,
    "harnessVersion": "0.1.7-rc.2", "harnessChannel": "desktop"
  },
  "total": 9423,
  "cols": ["id","desc","descZh","stars","forks","lang","topics","pushedAt","license","archived","homepage"],
  "rows": [["owner/repo","描述",null,1234,56,"TypeScript",["dsh-plugin"],"2026-09-26","MIT",0,null], …]
}
```

**列名表的顺序就是契约**（`test/catalog.test.mjs` 有一条专门测试）。
行序也**原样保留采集端的排序**（star 降序 → id 升序）—— 排序规则只实现一次。

## 三、性能：三个决定

### ① 一次取全量，之后本地搜

索引整份（约 1.6MB JSON / 约 700KB gzip）一次性给到浏览器内存，搜索在本地做。

| 方案 | 按键到出结果 | 代价 |
|---|---|---|
| 每敲一个字都问服务器 | 一次网络往返（本机 ~5ms，但仍然要等） | 服务端要维护检索索引 |
| **本地建索引 + 本地检索**（当前做法） | **< 10ms** | 首次建立约 15ms，常驻约 1.2MB 字符串 |

代价是首次传输。所以配合 ② 与 ③ 把它摊薄。

### ② 服务端 gzip + 条件请求

- 客户端声明 `accept-encoding: gzip` 时，服务端直接压好再发（1.6MB → 约 700KB）。
- 磁盘缓存带 ETag：30 分钟 TTL 内直接用；超过 TTL 走 `If-None-Match`，
  没更新时远端只回 304，**不传 body** —— 这就是「刷新几乎不花钱」的原因。

### ③ 虚拟滚动 + 模块级缓存

| 做法 | 效果 |
|---|---|
| 只渲染视口里的行（绝对定位 + overscan 上下各 6 行） | 九千多行 DOM 会卡，20 行不会 |
| 行组件用 `memo` 包住，只传原始值（`index`） | 滚动时每帧只渲染进出视口的那一两行 |
| payload 存在模块级变量里 | 面板切走再切回来是瞬时的，不重新取数 |

> ★ 行高是 JS 常量 `ROW_H`（96）与内联样式，**CSS 里不重复定义高度** ——
> 虚拟滚动的位置计算依赖它，两个地方各写一份迟早会不一致。

## 四、数据从哪来（读取顺序）

```
① <包根>/catalog/index.json 存在？
   → 是：本地仓库检出（开发场景），直接读文件，0 次网络请求（source: checkout）
② 磁盘缓存 ~/.dsh/storages/dsh-plugins-market/index-cache.json
   → TTL（30 分钟）内直接用（source: cache）
   → 超过 TTL：条件请求（source: remote / remote-304）
③ 都没有 / 拉取失败
   → 包内 catalog/snapshot.json（source: bundled）
```

每一层都如实标注 `source`，面板顶部与「关于」里都会显示 ——
用户永远能知道「我看到的是哪一份、有多旧」。

可以用环境变量覆盖索引地址（调试用）：`DSH_PLUGINS_MARKET_INDEX_URL`。

> ★ **远程那条路在开发机上永远走不到**（仓库检出里就有完整索引，直接读本地文件），
> 而**装到别人机器上时走的恰恰是它**。所以 `test/remote.test.mjs` 起了一个本地
> HTTP 服务器扮演远程，把四种情况都跑一遍：正常下载、条件请求拿到 304、
> 服务器 5xx、返回的形状不对 —— 外加一条「冷启动 + 没网 → 包内快照兜底」。

## 五、错误处理：降级，不罢工

| 坏在哪 | 表现 | 处理 |
|---|---|---|
| 拿不到 `webServer` 服务 | 面板没有数据接口 | 写一行 stderr 日志，**不抛错**（harness 照常启动） |
| `webServer.register` 抛错（路由冲突等） | 同上 | 同上 |
| 上下文构建失败 | 所有 RPC 返回可读错误 | 降级成一个只报错的 dispatch |
| 远程索引拉不到 | 用缓存或包内快照 | `meta.error` 如实回报，面板顶部显示黄点 |
| 远程索引形状不对 | 用上一份可用数据 | 同上，不会拿半个文档渲染出半个列表 |
| 面板组件渲染抛错 | 那一块变成错误提示 + 重试按钮 | 自备错误边界（class 组件） |
| 客户端半整体加载失败 | 侧栏没有图标 | `test/bundle.test.mjs` 的静态约束提前拦住 |

## 六、跨版本注意

面板只用**各版本都在的** API：

| 位置 | 用的东西 | 为什么安全 |
|---|---|---|
| 服务器半 | `ctx.effect(fn)`、`webServer.register({kind,path,handler})` | cordis 核心 + dsh web 的稳定接口，0.1.5 → 0.1.7 都是这个形状 |
| 客户端半 | `slots.inject(slot, cb)` / `slots.register({name,id,order,label,key}, renderer)` | 同上 |
| 客户端半的 require | 只有 `react` | 它是 shell 内置的 baseline seed word |

刻意**不**用的东西：`webServer.registerFallback`（0.1.7 才有）、
`pluginPackages` / `pluginInventory`（0.1.7 才有，且形状未定）、
任何 `@deepseek-ai/dsh-client-*` 包（虽然能 require，但每多一个依赖就多一个跨版本风险）。

详见 [`版本兼容.md`](./版本兼容.md)。
